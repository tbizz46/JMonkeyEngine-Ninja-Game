# Issue 8: sound effects and music

Work: [issue #8](https://github.com/tbizz46/JMonkeyEngine-Ninja-Game/issues/8).
This change builds on the blue/red uniforms in PR #7.

The game now plays original background music and nine effect cues. The
player can turn music and effects on or off separately with M and N.
Sound preferences last for the session and survive rematches.

## All code changes

1. **`src/mygame/DuelState.java`**: added an engine-free `Event` enum,
   an event queue, and `drainEvents()`. Successful sword attacks, kicks,
   jumps, landings, hits, and blocks emit distinct events. Misses emit
   the swing cue without a hit cue. Reset clears pending events. Combat
   damage, range, timing, and movement rules remain the same.
2. **`src/mygame/GameAudio.java`**: added the sound director and native
   audio backend. It consumes confirmed combat events once, plays round
   start and win/lose cues at state transitions, and controls the music
   loop. Music follows the actual native playback state, so a source that
   unexpectedly resumes is silenced again during pause/mute. Music and
   effects have separate toggles. Muted/paused events
   are discarded so they cannot play late. Pause stops active effects
   and pauses music; resume and rematch restore music if it is enabled.
   Rematch retains mute choices. Three buffered voices per effect allow
   sounds from both fighters to overlap. Cleanup stops all playback.
3. **`src/mygame/Main.java`**: initializes OpenAL after engine startup,
   registers its listener and context, and constructs GameAudio. If audio
   startup or asset loading fails, play continues with an actionable
   audio-unavailable message. Added M/N mappings, handlers, and visible
   state labels. Expanded the control strip from 54 to 76 pixels for a
   second audio-help row. Calls `gameAudio.sync()` each frame and closes
   playback before normal engine cleanup. Live checks now require native
   output, music playing, music paused, music resumed, and fight cues.
   Automated runs ignore live keyboard input to keep the checks repeatable.
4. **`tests/mygame/GameAudioTest.java`**: added a controlled playback backend
   to check event routing, no repeated per-frame cues, independent toggles,
   pause/resume, correction of unexpected paused music playback, ending
   cues, rematch preferences, no delayed muted cues,
   simulated unavailable-audio behavior, and safe cleanup. Also decodes all
   ten actual WAV files with jME and checks channels, bit depth, rate, and
   duration. Tests missing-file failure, misses without impact sounds,
   distinct block cues, and one jump/landing event pair.
5. **`run.command`**: includes GameAudioTest in `--test` after the existing
   combat and MonkeyWrench import checks.
6. **`package-mac.command`**: puts temporary packaging work on the external
   drive via TMPDIR and jpackage's `--temp`. This fixes the temporary-file
   failure encountered on the nearly full internal Mac disk. Existing asset
   packaging automatically includes the WAV files.
7. **`tools/generate_audio.py`**: added reproducible, original sound synthesis
   with a fixed seed. It creates noise-based swings, impacts, metallic block
   tones, jump/landing cues, start/win/lose phrases, and a twelve-second music
   loop with drums, plucked tones, and a soft drone. Each file is mono PCM,
   24 kHz, 16-bit, with capped peak level and short effect fades.
8. **`assets/Sounds/*.wav`**: added ten runtime files generated by the script.
   All are buffered; music loops at volume 0.22 and effects use volume 0.5.
   The existing OpenAL libraries are used; no new dependency was downloaded.
9. **`assets/Sounds/README.md`**: records each file, original provenance,
   output format, volume choices, and regeneration command.
10. **`README.md`**: adds M/N to the controls, describes audio behavior,
    updates the prior no-sound statement, and links to this change list.
11. **`.gitignore`**: excludes the `.lwjgl/` native extraction cache created
    by the audio-enabled runtime.
12. **This file**: records the complete change list, validation, usability
    scope, and known gaps.

## Verification

- `./run.command --test` passed: combat, model imports, sound event routing,
  mute/pause/rematch behavior, simulated no-device behavior, missing audio,
  and decoding all ten WAV files.
- `./run.command --smoke` passed on the Apple M3. OpenAL initialized, music
  entered Playing, paused with the game, resumed for rematch, and fight effect
  cues were played through the native backend. The existing blue/red
  GPU check, kicks, movement, victory, and rematch checks also passed.
- The rebuilt Mac app passed the same live music/effect/pause/rematch
  checks. GameAudioTest also passed with its packaged runtime and WAV files.
- The packaged check caught music continuing during pause. The fix follows
  actual source status instead of cached status; a regression test covers
  silencing unexpected playback during pause. The final app check passed.
- `git diff --cached --check` passed.

The tests verify decoding, routing, and native playback states. They do not
verify the physical speaker volume or a listener's judgment of the mix.
The no-device path was simulated; a hardware device was not unplugged.
Other operating systems and a manual M/N keyboard session were not tested.

## Player workflow and usability review

The player opens the game and hears a quiet loop. Starting a round adds a
start cue. Accepted actions and confirmed contact have distinct feedback.
M/N can be used on the start screen, during a fight, or while paused. The
second control row shows both choices. Pause and focus loss quiet the game;
resume keeps the user's choices. Rematch is Enter as before. If audio is
unavailable, the player sees how to recover and can keep playing.

The old silent game lacked audible action feedback (**H1 — Show what is
happening**, Main's audio setup and combat playback). That issue is covered
by the event-driven effects and the live playback checks above. The review
also checked player terms, toggling back, existing key consistency, quiet
defaults and safe mute behavior, visible context, rematch preferences, a
small secondary control row, actionable failure text, and point-of-use help.
No further issue was found within this source-and-test scope. Manual
keyboard/layout review, physical audio output, and other platforms remain
coverage gaps.
